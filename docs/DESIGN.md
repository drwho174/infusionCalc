### 0.2. Что этот документ решает

1. **Карта экранов и потоков** — что где находится, как перейти, что происходит при back и смене данных (§3, §4).
2. **Каждый экран и каждая сцена** — назначение, структура, используемые компоненты Material 3, поведение ввода, состояния `default / loading / empty / error / warning / disabled / success` (§4).
3. **Токены** — палитра Calc1 (light/dark), производные роли, сигнальные пары, типографика, отступы, радиусы, размеры, тач-цели, движение, elevation (§7).
4. **Доступность** — WCAG 2.2 AA, `contentDescription`, семантика, порядок фокуса, масштаб шрифта 200 %, TalkBack, edge-to-edge (§8).
5. **Локализация RU/EN** — правила, форматы чисел и единиц, реестр ключей, переполнение строк, ограничение смены языка по версии Android (§9).
6. **Крайние случаи** — нулевая концентрация, отсутствие веса, огромные значения, длинные названия, удаление препарата и др. (§10).
7. **Трассировка и приёмка** — матрица «требование ТЗ → экран/компонент/состояние» (§11), чек-лист приёмки дизайна (§12), открытые вопросы и пробелы (§13).

### 0.3. Что в этот документ сознательно не входит

Архитектура и версии библиотек (`docs/research-stack.md`, t6), формулы и пороги (`docs/SPEC.md` §6), клиническая аргументация (`docs/research-clinical.md`), юридическая формулировка дисклеймера (§7.4 ТЗ, OQ-17), макеты высокой точности и иконки. Функции вне области v1.0 (капли/мин, профили пациентов, журнал, облако, экспорт, планшетный двухпанельный режим, педиатрия) **не проектируются** — §1.3 ТЗ.

## 2. Аудитория, контекст и следствия для дизайна

Содержание — из ТЗ §2.1–2.2; здесь только то, что меняет решения дизайна.

| Персона | Контекст | Следствие для дизайна |
|---|---|---|
| Врач ОРИТ | Проверяет назначение, спешит, нужна проверяемость | Строка подстановки + раскрываемый расчёт + диапазон под полем дозы; крупный результат |
| Медсестра | У постели, часто в перчатках, одной рукой, ночная смена | Тач-цели 48 dp, основные действия внизу, тёмная тема, крупные цифры, живой пересчёт |
| Студент | Учится считать, не знает единиц | Раскрываемая формула с подстановкой, пояснение единиц, подсказка диапазона, дисклеймер |

Общие требования к среде: плохое освещение (тёмная тема обязательна), масштаб шрифта до 200 %, узкие экраны до 320 dp, возможная работа в альбомной ориентации. Экран **не** открывает клавиатуру сам (FR-CALC-15).

### 3.3. Навигационная модель

- Одноактивити, Navigation 3, back stack — данные (FR-NAV-01); глубина от стартового экрана ≤ 3 (FR-NAV-04).
- Нижней навигации нет; deep links и внешние ссылки отсутствуют (FR-NAV-03).
- Верхняя панель: одна строка — «назад» (кроме S-1 и S-0), заголовок, одно контекстное действие и/или overflow. Заголовок S-2 — название препарата (2 строки максимум, полное имя — в карточке и в описании TalkBack).
- Диалоги и листы — overlay-сцены поверх записи стека; форма под ними не теряет ввод (FR-NAV-09).
- Состояние экрана сохраняется, пока запись в стеке (FR-NAV-06); после смерти процесса настройки и стек восстанавливаются; вес запрашивается при следующем запуске (FR-NAV-08).
- Предиктивный back поддерживается; анимации отключаются при системном «убрать анимации» (NFR-UI-08).

### 3.4. Edge-to-edge и системные вставки

- `enableEdgeToEdge()` до `setContent` (NFR-STACK-08).
- Верхние панели учитывают статус-бар; прокручиваемый контент — `Scaffold` insets.
- Поля ввода используют `imePadding()`: поле в фокусе поднимается над клавиатурой (VAL-14, NFR-A11Y-09).
- Нижние панели действий (S-0, S-4) — `navigationBarsPadding()` + `imePadding()`; снекбар не перекрывает нижнюю панель и клавиатуру.
- Карточка результата — вне зоны IME (она над формой), поэтому результат виден при открытой клавиатуре (DS-2, §4.3).

## 4. Экраны и сцены

Общие правила для всех экранов:

- фон — `surface`, сгруппированный контент — `surfaceContainer*` (значения — §7.3); хардкод-цветов нет (NFR-UI-01);
- каждый экран имеет состояния из §4.0; «не бывает состояния без текста»: любое нештатное состояние объяснено словами;
- заголовки секций — `heading()`; порядок обхода TalkBack — визуальный (§8.3);
- все интерактивные элементы ≥ 48×48 dp, зазор между соседними ≥ 8 dp (NFR-A11Y-04);
- действия, меняющие данные, подтверждаются или отменяемы (DS-5, FR-CUSTOM-09).

### 4.1. S-0 — Дисклеймер первого запуска

Назначение: юридически и этически корректный вход; объяснить, что приложение — калькулятор, а не назначение. Без верхней панели, контент по центру, прокручивается.

1. Иконка/акцент (не декоративная картинка на весь экран).
2. Заголовок «Калькулятор скорости инфузии» (`headlineSmall`).
3. Три тезиса (`bodyLarge`, по строке): «Считает скорость инфузии по дозе и дозу по скорости» · «Единицы дозы и концентрация берутся из данных препарата» · «Справочный инструмент. Не заменяет назначение и проверку врачом».
4. Кнопка «Принять и продолжить» (filled, 56dp, на всю ширину с отступами 16dp).
5. Текстовая кнопка «Полный текст дисклеймера» → S-7.
6. Сноска «Работает офлайн. Данные остаются на устройстве.»

Состояния: только default. При ошибке сохранения факта принятия — снекбар «Не удалось сохранить настройку, попробуйте ещё раз»; экран не блокируется, принятие повторится при следующем запуске.

Доступность: порядок обхода — заголовок → тезисы → кнопка → ссылка → сноска; текст читается TalkBack целиком до кнопки (FR-DISC-01).

### 4.2. S-1 — Список препаратов (стартовый экран)

Назначение: выбрать препарат за 1–2 тапа, найти свой, добавить новый.

Структура: `TopAppBar` (заголовок + иконка настроек) → `SearchField` (C-5) → чипы фильтра «Все / Избранное / Мои» (C-6) → `LazyColumn` из `DrugRow` (C-4) → `ExtendedFloatingActionButton` «Добавить».

Сортировка по алфавиту текущего языка; избранные **не выносятся в отдельную секцию** — отмечены заполненной звездой на своём алфавитном месте.

Состояния: default (список) · loading (сид каталога: скелетон 6 строк, «Готовим каталог препаратов…») · empty-Мои («У вас пока нет своих препаратов» + «Добавить препарат») · empty-Избранное («Нет избранных препаратов» + подсказка) · empty-поиск («Ничего не найдено по запросу “{запрос}”» + «Добавить “{запрос}”») · error (сбой Room: «Не удалось загрузить список препаратов» + «Повторить») · success (снекбар после добавления/удаления).

Доступность: строка — один узел (`mergeDescendants`); звезда — отдельный переключатель со `stateDescription`; область нажатия звезды 48dp при иконке 24dp; счётчик найденного озвучивается через live-region после паузы ввода.

### 4.3. S-2 — Калькулятор (главный экран)

Назначение: на одном экране получить скорость по дозе и дозу по скорости, увидеть проверку диапазона и состав расчёта.

Порядок блоков фиксирован: **Результат → Концентрация → Доза → Скорость → Расчёт** (v1.1: поля веса в калькуляторе нет — вес глобальный для сессии).

- `ResultCard` (C-1) закреплена сверху: значение + статус-чип + строка подстановки.
- Концентрация — селектор пресетов препарата (C-7): текущая «40 мг / 250 мл = 0,16 мг/мл» + «▾»; тап открывает S-2b со списком предустановок. Для своего препарата — «Изменить пресеты» → S-4; для каталожного — «Скопировать в мои».
- Доза — `NumericField` с суффиксом единицы; под полем постоянная подсказка диапазона «Диапазон: 0,05–0,2 мкг/кг/мин» (видна **до** ошибки). Нажатие на суффикс открывает пояснение «Единицы заданы в препарате» + «Открыть препарат».
- Скорость — `NumericField` (computed, с «≈»); при ручном вводе становится источником, доза пересчитывается.
- «Показать расчёт» (C-12) раскрывает формулу с подстановкой; caption-ссылка «Калькулятор не заменяет назначение врача» → S-7.

Состояния (полная таблица — §4.0): default, loading, computed-in-range / computed-no-range, warning (выше диапазона), critical (критически высокая), error-concentration / error-unit, drug-deleted. Пока ввод некорректен, оценка диапазона не вычисляется; `warning` и `error` одновременно не показываются. Если вес сессии не задан — карточка результата показывает «Укажите вес» и ведёт в S-W.

Overlay-сцены (не записи back stack, FR-NAV-09): `S-2a` подтверждение смены схемы/препарата, `S-2b` лист разовой концентрации, `S-2c` экран сверки high-alert, `S-2d` лист суточной дозы. Форма под ними сохраняет ввод.

Доступность: ResultCard — первый узел, `liveRegion=Polite`, озвучивание после 600 мс; поля — имя + единица + значение в описании; ошибки — `error()` + текст.

### 4.4. S-3 — Карточка препарата (объединена с S-4, v1.2)

С v1.2 отдельного экрана нет: дозирование, концентрации и заметки показываются и редактируются в S-4; переход «К расчёту» — оттуда же. Ниже — историческое описание.

Структура: верхняя панель (название + overflow) → шапка (название, бейдж «Каталог»/«Мой препарат») → секции-`SectionCard`: **«Дозирование»** (единицы, диапазон, округление), **«Концентрации»** (список пресетов: «4 мг / 4 мл = 1 мг/мл», «4 мг / 1000 мл = 4 мкг/мл»), **«Заметки»**. Разделы «Идентификация» (МНН, торговое) и «Источник» в карточке и форме не отображаются (v1.1).

Нижняя панель: «К расчёту» (filled); для своего препарата — «Изменить» (outlined) и «Удалить» (в overflow, цвет `error`).

Состояния: default · catalog (без «Изменить»/«Удалить») · custom · без диапазона · loading · error · препарат удалён → возврат.

### 4.5. S-4 — Добавление и редактирование препарата

Назначение: завести препарат с корректными единицами и концентрациями; при редактировании — изменить их.

Поля формы: Название (обязательно, 1–80) · Единицы дозы · Дозировка на кг · База времени · Диапазон доз (от/до) · **Концентрации** — список пресетов (строка с концентрацией, «Изменить»/«Удалить») + «Добавить концентрацию». Новая концентрация также добавляется чипсом в блоке «Концентрация» на экране расчёта (S-2). Пресет задаётся как «масса + объём» с единицей массы. · Заметки (многострочное поле). МНН, торговое название и источник не запрашиваются (v1.1).

Нижняя панель: «Сохранить» (56dp, на всю ширину) + «Отмена» в верхней панели. «Сохранить» недоступна, пока форма невалидна; рядом — одна строка, что именно не заполнено.

Валидация (по blur): название не пусто ≤80; масса >0 ≤1 000 000; объём >0 ≤10 000 мл; единицы выбраны; диапазон «от < до» и оба >0.

Состояния: default · editing (prefilled) · dirty · invalid · saving (поля read-only) · error сохранения (снекбар, данные не теряются) · success (возврат + снекбар) · «уйти с несохранёнными» → диалог MSG-22.

### 4.6. S-5 — Настройки

Секции-карточки: **«Тема»** (Системная / Светлая / Тёмная) · **«Язык»** (Системный / Русский / English; на Android 13+ применяется сразу через per-app locale, на более старых — только системный с пояснением) · **«О программе»** (название, версия; строка открывает S-6) · офлайн-примечание.

Сознательно отсутствуют: выключатели предупреждений, «простой режим», выбор точности округления, единицы веса (только кг), профили пациентов. Dynamic color отсутствует (зафиксировано).

### 4.7. S-6 — О приложении

Иконка приложения, название, версия (`versionName`), назначение одним абзацем, автор, кликабельные email и Telegram, примечание «приложение работает офлайн, данные не передаются».

### 4.8. S-7 — Дисклеймер (полный текст)

Что делает/не делает приложение; расчёт справочный; ответственность клинициста; проверка единиц, веса, концентрации; запрет использования как единственного источника; отсутствие гарантий; версия текста и дата. Текст — из ТЗ §7.4 (клиническая/юридическая формулировка); дизайн задаёт оформление и точки входа. Верхняя панель с «Назад» есть всегда.

### 4.9. S-W — Вес пациента (при запуске)

Назначение: задать вес один раз для всех расчётов в текущей сессии.

Структура: заголовок «Вес пациента, кг», `NumericField` (кг, цифровая клавиатура), подсказка «например, 70», кнопка «Продолжить» (56dp, на всю ширину), сноска «Вес действует для всех препаратов в этом сеансе и не сохраняется на устройстве».

Состояния: пусто (кнопка недоступна) · valid (продолжить) · error (0 или вне 20–200 кг — «Проверьте вес»). Пока вес не подтверждён, калькулятор недоступен.

Доступность: при открытии S-W поле в фокусе и клавиатура показана (единственный экран, где это оправдано); «Продолжить» ≥48dp.

## 5. Поведение ввода и живого пересчёта

### 5.1. Модель состояния числового поля

`Empty → Partial → Valid → Error`. Partial («0,», «,») — **не ошибка** и не красный цвет; вычисленное поле показывает «—». Error — только содержательная ошибка (концентрация 0, выход за предел); недопустимый символ просто не попадает в поле.

### 5.2. Правила ввода (обязательны к реализации)

| № | Правило |
|---|---|
| N-1 | Один разделитель `,` или `.` |
| N-2 | Разделитель не может быть первым; при blur «,5» → «0,5» |
| N-3 | Максимум 4 знака после разделителя |
| N-4 | Максимум 7 знаков до разделителя |
| N-5 | Ведущие нули схлопываются при blur («007» → «7») |
| N-6 | Без группировки тысяч ни в поле, ни в результате |
| N-7 | Ввод не меняется, пока поле в фокусе; нормализация по blur |
| N-8 | Вставка: извлекается первое число, остальное отбрасывается |
| N-9 | Минус недоступен; отрицательные значения не вводятся |
| N-10 | Пределы полей (вес ≤300 кг, скорость ≤999,9 мл/ч, доза ≤1 000 000) — ошибка, а не усечение |
| N-11 | `KeyboardType.Decimal`, `ImeAction.Next`, «Готово» на последнем |
| N-12 | Плейсхолдер — пример («например, 70»), а не предзаполненное значение |
| N-13 | Ошибка — по blur, не на каждый символ |
| N-14 | В вес нельзя вставить «кг» — единица это суффикс |

Клавиатура и фокус: экран не фокусирует поле автоматически; тап по полю → клавиатура; «Готово»/тап вне поля снимает фокус и нормализует. Поле в фокусе прокручивается над IME; карточка результата (сверху) не перекрывается. Значения формы сохраняются в пределах сессии (поворот, уход в фон); при перезапуске вес запрашивается заново (S-W).

### 5.3. Живой пересчёт

- Источник — поле, изменённое последним; второе поле — вычисленное («≈» + «пересчитано из дозы/скорости»). Начало ввода в вычисленном поле делает его источником.
- Пересчёт никогда не меняет текст поля в фокусе; не запускается от собственного результата.
- Вычисленное округляется только для отображения; в памяти — неокруглённое (round-trip без накопления погрешности).
- Пересчёт не выполняется при: пустом/неполном источнике, не заданном весе сессии (для схем «на кг»), концентрации 0/не заданной, отсутствии единиц, выходе за предел. Карточка результата показывает **причину**, а не «0».
- Озвучивание: live-region с задержкой 600 мс, не на каждое нажатие; статус диапазона озвучивается вместе со значением.

### 5.4. Ошибки, предупреждения, безопасность

Таксономия: ошибка ввода (блокирует расчёт) · блокирующее состояние (нет единиц/концентрации) · предупреждение о дозе (warning, не блокирует) · критическое предупреждение (critical, не блокирует) · информация · подтверждение (диалог) · результат действия (снекбар).

Предупреждения **не модальные** и не закрываются пользователем: модальное окно при высокой дозе закроют рефлекторно. Текст предупреждения всегда содержит введённое значение, диапазон и «что проверить» (единицы, вес, концентрацию). Критическое дополнительно меняет статус результата на красный, но не блокирует ввод.

Матрица сообщений (RU/EN) — в §9.3 research-ux и в ТЗ §7; дизайн фиксирует уровни: warning (жёлтый) / critical (красный) / error / blocking / info / confirm.

Округление (отображение): скорость — 1 знак (при <1 — 2 знака); доза — до 3 значимых цифр, не более 4 знаков после разделителя; вес — 1 знак; концентрация — 3 значимые цифры. Округление меняет только отображаемое, не введённое значение.

## 7. Дизайн-токены

### 7.1. Принципы

1. Только роли `MaterialTheme.colorScheme` / `typography` / `shapes`; хардкод-цветов и размеров нет.
2. Dynamic color **выключен** (требование заказчика): схема фиксированная, сигнальные цвета сохраняют смысл независимо от обоев.
3. Цвет никогда не единственный носитель смысла: иконка + текст (+ граница).
4. `outlineVariant` — только декоративные разделители (контраст 1,66:1 светлая / 1,84:1 тёмная не проходит 3:1).
5. Пары «текст/фон» проверены по WCAG 2.2 расчётом относительной яркости (не «на глаз»).

### 7.5. Типографика

База `Calc1Typography` + роли калькулятора. Значение результата — `displaySmall` 36/44sp SemiBold `tnum` (на широких экранах `displayMedium` 45/52). Заголовки: `headlineSmall` 24, `titleLarge` 22 (верхняя панель), `titleMedium` 16 (секции/строки). Текст: `bodyLarge` 16, `bodyMedium` 14, `bodySmall` 12. Кнопки/чипы `labelLarge` 14, бейджи `labelMedium` 12.

Правила: все живые числа — табличные цифры (`tnum`); единица — на роль меньше значения и не жирная; ручных `fontSize` вне токенов нет; минимум 12sp; фиксированных высот у текстовых контейнеров нет (200 % шрифта).

### 7.6. Отступы, радиусы, размеры, движение

- Отступы по сетке 8dp: `xs=4, s=8, m=12, l=16, xl=24, xxl=32`.
- Радиусы: `xs=4, s=8, m=12 (диалоги), l=16 (карточки/поля), xl=24 (листы), pill=50 %`.
- Размеры: тач-цель ≥48×48dp (без исключений), поле 56dp, кнопка 48/56dp, FAB 56dp, строка препарата 72dp, верхняя панель 64dp, иконка 24dp (в тексте 20dp), контент ≤640dp на планшетах.
- Движение: смена экрана 300 мс `EmphasizedDecelerate/Accelerate`; раскрытие формулы 200 мс; снекбар 150 мс; статус результата 150 мс (только фон). При «убрать анимации» — всё мгновенно. Значение результата не «прокручивается». Карточки — 0dp + тональный контейнер (без теней).

## 8. Доступность (WCAG 2.2 AA)

Цель AA для всех экранов, с элементами AAA (контраст основного текста, тач-цели). Ключевые обязательства:

- **1.4.1 Color**: статусы и ошибки — иконка + текст, никогда не только цвет.
- **1.4.3 / 1.4.11 Contrast**: измерено в §7; `outline` для границ (4,39/5,42:1), `outlineVariant` — только декор.
- **1.4.4 / 1.4.10 / 1.4.12**: 200 % шрифта и 320dp без потери; нет `maxLines=1` на важных подписях.
- **2.5.8 / 2.5.5 Target Size**: 48dp ≥ AAA.
- **2.5.7 Dragging**: нет действий только перетаскиванием (удаление — меню + диалог, не свайп).
- **2.4.3 / 2.4.6 / 2.4.7**: порядок фокуса = визуальный; `heading()` на секциях; видимый фокус (обводка `secondary` + свечение `primary`).
- **3.3.1 / 3.3.3 Error**: ошибка текстом + подсказка «как исправить».
- **4.1.2 / 4.1.3**: `mergeDescendants`, `stateDescription`, `error()`; статусные сообщения — live-region без перевода фокуса.

TalkBack-сценарии (обязательные): при открытии калькулятора сначала результат, затем форма; после ввода — объявление результата через 600 мс; правка вычисленного поля — «введено вручную»; ошибка — при уходе из поля, фокус не теряется; строка списка — одним узлом; удаление — диалог + снекбар с «Вернуть».

Семантика чисел: единица озвучивается развёрнуто («миллилитров в час», а не «мл/ч»); дробная часть — «две целых шесть десятых». Масштаб шрифта тестируется на 100/130/150/200 %. Одна рука/перчатки: основные действия в нижней трети, свайпы не единственный способ, длинных нажатий нет.

## 9. Локализация RU / EN

### 9.1. Правила

Все строки в ресурсах (`values/strings.xml` — базовый en, `values-ru/strings.xml`); строк в коде нет. Ключи `экран_элемент_роль`. Только позиционные аргументы (`%1$s`). Плюрализация — `plurals`. Никакой конкатенации фраз. Форматирование чисел/дат — по локали приложения, **не** по `Locale.getDefault()` (язык приложения может отличаться от системного). Названия препаратов — данные Room (двуязычные поля `nameRu/nameEn/innRu/innEn`); пользовательские не переводятся.

### 9.2. Числа и единицы

RU — запятая (`0,1`), EN — точка (`0.1`); ввод принимает оба; группировка тысяч не используется. Единица после числа — неразрывный пробел (`2,6 мл/ч` / `2.6 mL/h`). Скорость: `мл/ч` / `mL/h`; доза на кг в минуту: `мкг/кг/мин` / `mcg/kg/min`; масса: мг/мкг/г; объём: мл/mL; единицы действия: МЕ/ч (IU/h), ЕД/ч (units/h).

Запрещённые сокращения (для текстов интерфейса): `µg` → `mcg`; одиночное `U`/`Ед` → «единицы»; «в/в» в озвучиваемых текстах → «внутривенно»; `cc` → `мл`/`mL`.

### 9.3. Схемы единиц дозы (для формы препарата)

Данные (enum-код), не строки — полный закрытый список из SPEC FR-UNIT-03 (12 схем): `мкг/кг/мин` / `мкг/мин` / `мкг/кг/ч` / `мг/кг/ч` / `мг/ч` / `мг/мин` / `ЕД/ч` / `ЕД/кг/ч` / `ЕД/мин` / `мэкв/ч` / `г/ч` / `МЕ/ч` (EN: `mcg/kg/min`, `mcg/min`, `mcg/kg/h`, `mg/kg/h`, `mg/h`, `mg/min`, `units/h`, `units/kg/h`, `units/min`, `mEq/h`, `g/h`, `IU/h`). Подпись — из ресурсов (§9.2).

### 9.4. Длина строк

RU на 10–20 % длиннее EN; кнопки без фиксированной ширины, тексты кнопок до 3 слов; заголовки секций до 30 символов. Проверяемые переполнения: «Критически высокая доза» / “Critically high dose”, «Концентрация изменена для этого расчёта» / “Concentration changed for this calculation”.

Минимальный набор ключей строк — см. research-ux §13.7; финальный реестр формируется при реализации, naming-конвенция и формулировки безопасности зафиксированы здесь.

## 11. Трассировка к ТЗ

Дизайн-решения привязаны к требованиям ТЗ идентификаторами `FR-*`, `NFR-*`, `VAL-*`, `CALC-*`, `MSG-*` (использованы по тексту §3–§10). Ключевые соответствия: единая форма → `FR-CALC-01…03`, `D-1`; липкая карточка результата → `FR-CALC-07`; не-модальные предупреждения → `FR-SAFE-02/05/06`; единицы только через препарат → `FR-UNIT-09/10`; разовая концентрация (`should`) → `FR-CONC-06`; edge-to-edge → `NFR-STACK-08`; 48dp → `NFR-A11Y-04`. Полная матрица «требование → экран/компонент/состояние» — реестр, который расширяется при реализации; расхождения фиксируются в §13.

## 12. Критерии приёмки дизайна

1. Все экраны S-0…S-7 и сцены S-2a…S-2d описаны с состояниями и переходами.
2. Каждая пара «текст/фон» из §7 имеет измеренный контраст ≥ AA; сигнальные цвета — только парами.
3. Правила ввода N-1…N-14 и живого пересчёта §5 непротиворечивы и реализуемы.
4. Доступность: чек-лист §8 покрыт, TalkBack-сценарии выполнимы.
5. Локализация: правила §9 не зависят от системной локали; плюрали и аргументы корректны.
6. Крайние случаи E-1…E-20 покрыты поведением.
7. Нет противоречий с ТЗ; все расхождения — в §13.
