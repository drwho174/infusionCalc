## 1. Цели и границы

### 1.1 Цели продукта

| ID | Цель | Как проверяется |
|---|---|---|
| G-1 | За **один экран и без промежуточных кнопок** получить скорость инфузии по дозе и дозу по скорости, с автоматическим пересчётом в обе стороны | ACC-1, ACC-2 |
| G-2 | Исключить класс ошибок «единицы не того препарата»: единица дозы — свойство препарата из инструкции, а не настройка экрана | ACC-3, ACC-4 |

| G-5 | Работать офлайн и приватно: без сети, без аккаунта, без передачи данных | ACC-16, ACC-17 |

### 1.5 Принятые проектные решения (обязательны к исполнению)

Решения ниже снимают противоречия между research-документами. При конфликте текста требования с решением — действует решение; изменение решения возможно только новым решением с записью в этом разделе.

| ID | Решение | Обоснование / источник | Влияние на требования |
|---|---|---|---|
| **D-1** | **Направление расчёта — состояние формы, а не экран и не переключатель.** Оба поля («Доза», «Скорость») активны; источник — поле, изменённое последним; второе поле пересчитывается и помечается «≈». Отдельного переключателя направления ⛔ нет | Вводная заказчика; t3 U-1, U-2; t2 §5.4 описывал «переключатель направления» — **отменено** в пользу U-1 | FR-CALC-01…03 |
| **D-2** | **Единица дозы — свойство схемы дозирования препарата**, не глобальная настройка и не поле калькулятора. В калькуляторе единица не редактируется | t1 R1, §4.2; вводная заказчика; t3 U-4 | FR-UNIT-01…06, DATA-SCHEME |
| **D-3** | **Один препарат содержит 1…N схем дозирования**; индикация — часть ключа дозирования (вазопрессин 0,01 vs 0,03 ЕД/мин ✅; амиодарон нагрузка vs поддержка ✅). Плоское поле `doseUnit` из t2 §5.2 расширяется до сущности `DoseScheme` | t1 R13, §4.1; t2 §5.2 (базис модели) | DATA-SCHEME, FR-UNIT-09 |
| **D-4** | **Правка каталожного препарата = создание пользовательской редакции** (копия со ссылкой `derivedFromId`); встроенная карточка неизменяема, исходные `sourceUnits` сохраняются, доступна команда «Сбросить к источнику» | t1 §4.3 (шаг 4), t3 U-9 (read-only каталог) — совмещены без конфликта | FR-CUSTOM-06, DATA-DRUG-10, DATA-SCHEME-11 |
| **D-5** | **Концентрация берётся из препарата** (обязательное явно подтверждённое значение) и показывается как вычисленная строка `масса / объём = C`. Разовый пересчёт концентрации в калькуляторе — `should` (v1.0), только с пометкой «для этого расчёта» и без сохранения | t1 R5, §3.1, E7; t3 U-5 (⚠️ OQ-3 закрывается здесь) | FR-CONC-01…05 |
| **D-6** | **Вес — только ручной ввод, только кг**, сбрасывается при смене препарата и не переживает перезапуск процесса | t1 R4, W4; вводная заказчика; t3 U-6 | FR-WEIGHT-01…05 |
| **D-7** | **Четыре уровня пределов**, различающихся поведением: *подсказка диапазона* (всегда) → *предупреждение* (soft, не блокирует) → *критическое предупреждение* (не блокирует, красный статус) → *жёсткий предел* (блокирует: только значение из источника/протокола и технические пределы). Модальных окон при превышении дозы ⛔ нет | t1 §6.2 (soft/hard по DERS); t3 §9.2 (не блокировать обоснованные высокие дозы); совмещение: блокировка — только там, где есть источник/техника | FR-SAFE-01…08 |
| **D-8** | **Округление: один раз, на выводе, к ближайшему (`HALF_UP`)**; после округления скорости доза **пересчитывается и показывается как фактическая**. Промежуточные значения не округляются | t1 R3, §3.4, A5 (предпочтён вариант «к ближайшему»); t2 §6.3–6.4 | CALC-05, CALC-06, ACC-7 |
| **D-9** | **Капли/мин и `dropFactor` отсутствуют** в модели и UI (поле из t2 §5.2 удаляется) | ⛔ t1 R10, §6.7 п.1 | §1.3 п.1, NFR-STACK |
| **D-10** | **Группировка разрядов запрещена** и при вводе, и при отображении; принимаются оба десятичных разделителя (`,` и `.`), максимум 4 знака после разделителя. Неоднозначность «1,000» устраняется конструктивно (нет тысяч), см. VAL-06 | t1 R9, W11; t3 N-3, N-6 | VAL-01…06 |
| **D-11** | **Журнала расчётов нет** в v1.0 (ни локального, ни «по согласию»); нет сети, аналитики, аккаунта. Приложение не хранит персональных данных | t1 A6, §5.5; t2 §3.8; вводная «без облака» | NFR-PRIV-01…05, FR-SET-05 |
| **D-12** | **Каталог: числа только из открытого источника.** В v1.0 поставляются 5 верифицированных карточек (✅ DailyMed SPL) и до 14 карточек-кандидатов **без числовых доз** со статусом «требует сверки»; у кандидатов расчёт заблокирован до заполнения пользователем. Релизный гейт: ≥10 верифицированных карточек до публикации | t1 §8.1–8.3, A12; вводная «10–20 препаратов»; правило «без выдуманных значений» | FR-CAT-06, ACC-15 |
| **D-13** | **Десятичная арифметика: `BigDecimal`, парсинг из строки, персистентность в `TEXT`**; в модуле `:core-engine` запрещены `Double`/`Float`/`Math.round` | t2 §6.3–6.4 | NFR-QUAL-02, CALC-02 |
| **D-14** | **ЕД и МЕ — разные токены**, автоконвертация ⛔; соотношение задаётся только в карточке препарата и только с источником (вазопрессин: 1 мг = 530 ЕД ✅) | t1 R7 | FR-UNIT-04 |
| **D-15** | **Локаль форматирования чисел — из настроек приложения**, а не `Locale.getDefault()`; ввод всегда принимает оба разделителя | t3 §13.2; t2 §4.4 | NFR-I18N-03 |

### 2.3 Сценарии (обязательные к прохождению)

Формат: шаги → ожидаемый результат → связанные требования. Сценарии используются как основа UI/e2e-тестов.

**SC-1. Доза → мл/ч за минимум действий (врач, 15 секунд)**
1. Запуск → S-W «Вес пациента»: ввод `70` → S-1 «Препараты» (после первого запуска S-0 → S-W → S-1).
2. Тап по «Норэпинефрин» (каталожная карточка) → S-2.
3. Ввод дозы `8` (схема `мкг/мин` из препарата, концентрация 4 мкг/мл — выбранный пресет; вес для схемы без `/кг` не требуется — FR-WEIGHT-03).
4. Результат: `≈ 120 мл/ч`, статус «в диапазоне» (8 мкг/мин внутри 2–12 ✅), строка подстановки «8 мкг/мин · 4 мкг/мл».
→ FR-CALC-01…07, FR-UNIT-01…03, FR-CONC-01…02, FR-SAFE-01; ACC-1, ACC-5.

**SC-2. мл/ч → доза за те же два поля (медсестра)**
1. S-1 → «Никардипин» → S-2 (схема `мг/ч`, концентрация 0,1 мг/мл ✅).
2. Ввод скорости `30` в поле «Скорость инфузии» (вес для схемы «в час без /кг» не требуется).
3. Доза пересчитывается: `≈ 3 мг/ч`; подпись «пересчитано из скорости».
→ FR-CALC-01…04, FR-WEIGHT-03 (вес не обязателен для абсолютных схем), CALC-02; ACC-2; golden TEST T4.

**SC-3. Смена направления без переключателя**
1. В S-2 введена доза `0,01` (вазопрессин, ЕД/мин, 0,1 ЕД/мл) → скорость `≈ 6 мл/ч` (✅ T8).
2. Пользователь начинает печатать в поле скорости `5`.
3. Поле скорости становится источником, доза пересчитывается (`≈ 0,0083 ЕД/мин`), подпись меняется на «пересчитано из скорости». Никаких переключателей не нажато.
→ FR-CALC-03, FR-CALC-05; ACC-1, ACC-2.

**SC-4. Высокая доза: предупреждение, но не блокировка**
1. Никардипин, концентрация 0,1 мг/мл, ввод дозы `20` мг/ч (диапазон 5–15 ✅).
2. Результат `≈ 200 мл/ч`, статус «выше диапазона», баннер: «Доза выше указанного диапазона. Диапазон: 5–15 мг/ч. Проверьте единицы, вес и концентрацию».
3. Расчёт остаётся доступным, значение не скрывается; кнопки «ОК/Продолжить» нет.
→ FR-SAFE-02, FR-SAFE-05, MSG-01; ACC-6.

**SC-5. Жёсткий предел из источника блокирует расчёт**
1. Препарат с заданным `maxRate` (например, из протокола) — ввод скорости выше предела.
2. Результат заменяется сообщением «Скорость выше допустимой для этой схемы. Расчёт заблокирован», поле подсвечено, подсказка — что изменить.
→ FR-SAFE-04; ACC-6; MSG-02.

**SC-6. Медсестра добавляет свой препарат**
1. S-1 → FAB «Добавить препарат» → S-4.
2. Название «Норадреналин 2 мг/50 мл»; **пресет концентрации**: масса `2` мг, объём `50` мл (предпросмотр `= 0,04 мг/мл`); **единицы дозы** — выбор `мкг/кг/мин` из закрытого списка (обязательный шаг); диапазон необязателен.
3. «Сохранить» → возврат в S-1, снекбар «Препарат добавлен», бейдж «Мой препарат».
4. В S-2 бейдж «Мой препарат» и предупреждение-информация: «Значения не проверены по инструкции».
→ FR-CUSTOM-01…05, FR-UNIT-08, FR-SAFE-07; ACC-3, ACC-4.

**SC-7. Правка единиц каталожного препарата**
1. S-2 норэпинефрина → «Откуда единицы» → S-3 (карточка, read-only, бейдж «Каталог»).
2. «Скопировать в мои препараты» → S-4 (предзаполнено), смена схемы с `мкг/мин` на `мкг/кг/мин`.
3. При сохранении — подтверждение: «Схема отличается от исходной (исходно: мкг/мин)». Сохраняется как редакция (`derivedFromId`), доступно «Сбросить к исходной схеме».
4. При открытии редакции в расчёте — индикатор «схема изменена пользователем».
→ FR-UNIT-06, FR-CUSTOM-06, D-4; ACC-3.

**SC-8. Ошибочный вес**
1. S-W, ввод веса `150` (в килограммах, но пользователь имел в виду фунты).
2. Предупреждение «Проверьте вес: 150 кг выглядит необычным. 150 lb ≈ 68 кг» — не блокирует, видно рядом с полем.
→ FR-WEIGHT-04, MSG-06; ACC-6; TEST T15.

**SC-9. Удаление пользовательского препарата**
1. S-3 «Мой препарат» → overflow → «Удалить» → диалог с названием препарата.
2. Удаление → возврат в S-1 → снекбар «Препарат “X” удалён» + «Вернуть» (5–7 с).
→ FR-CUSTOM-09, FR-CAT-05; ACC-10.

**SC-10. Первый запуск и дисклеймер**
1. Первый запуск → S-0: три тезиса + «Принять и продолжить» + «Полный текст дисклеймера» + сноска «Работает офлайн. Данные остаются на устройстве».
2. Принятие сохраняется локально; при следующих запусках S-0 не показывается.
3. Из S-5/S-6/S-7 дисклеймер доступен всегда, в том числе с S-2 в один тап.
→ FR-DISC-01…05; ACC-15.

**SC-11. Поиск на другом языке**
1. Интерфейс RU; в поиске вводится `noradrenaline` → находится «Норэпинефрин» (поиск по `nameRu` + `nameEn`).
2. В интерфейсе EN вводится `гепарин` → находится Heparin.
→ FR-CAT-03; ACC-18.

**SC-12. Ошибка ввода не «наказывает» пользователя**
1. Ввод `0,` в поле дозы — состояние Partial: результат `—`, красного нет.
2. Ввод `,5` → по потере фокуса нормализуется в `0,5`, результат пересчитывается.
3. Ввод `1.2.3` — второй разделитель не вводится, подсказка о формате.
→ VAL-02, VAL-05, VAL-07; ACC-8.

## 3. Термины, обозначения и единицы

### 3.1 Термины

| Термин | Определение |
|---|---|
| Доза (`D`) | Количество препарата за единицу времени с учётом или без учёта массы тела — в единицах схемы (`мкг/кг/мин`, `мг/ч`, `ЕД/мин` …) |
| Скорость инфузии (`R`, `Q`) | Объём раствора за час, **мл/ч** — единственная скорость в продукте |
| Концентрация (`C`) | Количество препарата в 1 мл готового раствора: `C = m / V` |
| Схема дозирования | Тройка (`amount`, `perKg`, `perTime`) + индикация + диапазон + источник; свойство препарата |
| Вес (`W`) | Масса тела пациента, вводимая вручную, **кг** |
| Шаг насоса | Дискретность программирования скорости, по умолчанию 0,1 мл/ч ⚠️ (OQ-1) |
| Каталожный препарат | Карточка, поставляемая с приложением; read-only |
| Пользовательский препарат | Карточка, созданная пользователем; редактируемая; статус «не проверено» |
| Редакция | Пользовательская копия каталожного препарата (`derivedFromId`) с сохранённым исходником |
| Подсказка диапазона (hint) | Постоянно видимая строка «Диапазон: X–Y ед.» под полем дозы |
| Предупреждение (soft) | Неблокирующее сообщение о выходе за диапазон/правдоподобность |
| Критическое предупреждение | Неблокирующее сообщение о значении, значительно превышающем диапазон; красный статус результата |
| Жёсткий предел (hard) | Блокировка расчёта при превышении предела, заданного источником/протоколом |
| Технический предел | Блокировка при физически невозможных значениях (C ≤ 0, W ≤ 0, R > 999,9 мл/ч) |
| «≈» | Маркер вычисленного и округлённого значения (в отличие от введённого) |

### 3.2 Единицы количества препарата

| Величина | RU | EN | Токен модели | Примечание |
|---|---|---|---|---|
| Микрограмм | мкг | mcg | `MCG` | `µg` в UI ⛔ (читается как `mg`) |
| Миллиграмм | мг | mg | `MG` | 1 мг = 1000 мкг |
| Грамм | г | g | `G` | Для MgSO₄, KCl |
| Единица действия | ЕД | units | `UNIT` | Инсулин, гепарин (USP units ✅), вазопрессин, окситоцин |
| Международная единица | МЕ | IU | `IU` | Отдельный токен; ≠ ЕД автоматически ⛔ |
| Миллиэквивалент | мэкв | mEq | `MEQ` | Электролиты (KCl). Единица `ммоль` — OQ-11 |

### 3.3 Время, вес, объём

| Величина | Значение в продукте | Примечание |
|---|---|---|
| Время схемы | только `мин` / `ч` | Секунды ⛔ (t1 A4) |
| Вес | кг, единственная единица | Фунты — только текст подсказки: 1 lb = 0,45359237 кг, 150 lb ≈ 68 кг ✅ |
| Объём | мл | Литры — только при вводе объёма растворителя (пересчитываются в мл) |
| Скорость | мл/ч | `мл/мин`, `капли/мин` ⛔ |

## 6. Правила расчёта и округления

### 6.1 Обозначения и модель единиц

| Символ | Смысл | Единица |
|---|---|---|
| `D` | Доза | единицы схемы (`мкг/кг/мин`, `мг/ч`, `ЕД/мин` …) |
| `W` | Вес | кг |
| `C` | Концентрация | единица количества / мл |
| `R` (в тексте также `Q`) | Скорость инфузии | мл/ч |
| `m`, `V` | Масса препарата и конечный объём раствора | единица количества, мл |
| `k` | Множитель времени: `60` при `PER_MINUTE`, `1` при `PER_HOUR` | — |
| `b` | Показатель веса: `1` при `perKg`, `0` иначе | — |

**CALC-01.** Любая схема раскладывается в тройку (`amount`, `perKg`, `perTime`); отдельных веток кода под конкретные препараты или конкретные схемы ⛔ не существует (t1 R2, §3.2).

**CALC-02.** Внутренние вычисления — `BigDecimal`: парсинг из строки, `MathContext.DECIMAL128` (или явный `scale = 10`), округление один раз на выводе (D-13).

### 6.2 Формулы

**CALC-03. Концентрация.**

```
C = m / V                                   (разведение массой)
C = C_раствор                               (готовый раствор)
C = (C_амп · V_амп) / V                     (разведение ампулой)
```

Требование к точности: `C` вычисляется без промежуточного округления; для отображения — 3 значащие цифры. Объём добавки считается пренебрежимым (допущение A1, t1 §3.1) — кроме случая `V < 10 × V_амп`, где включается предупреждение MSG-14.

**CALC-04. Прямой пересчёт: доза → скорость.**

```
R [мл/ч] = D · k · W^b / C
```

**CALC-05. Обратный пересчёт: скорость → доза.**

```
D = R · C / (k · W^b)
```

**CALC-06. Фактическая доза после округления скорости.**

```
R' = round(R, шаг насоса)                  (D-8, к ближайшему, HALF_UP)
D_факт = R' · C / (k · W^b)
```

`D_факт` показывается рядом с результатом как «фактически доставляется», если отличается от введённой/вычисленной дозы более чем на порог MSG-13 (⚠️ OQ-7).

**CALC-07. Обязательные к поддержке схемы и множители** (t1 §3.2, §3.3):

| № | Схема | `amount` | `perKg` | `perTime` | Множитель к «в час» | Формула `R`, мл/ч |
|---|---|---|---|---|---|---|
| 1 | мкг/кг/мин | MCG | да | мин | `W · 60` | `D·W·60 / C` |
| 2 | мкг/мин | MCG | нет | мин | `60` | `D·60 / C` |
| 3 | мкг/кг/ч | MCG | да | ч | `W` | `D·W / C` |
| 4 | мг/кг/ч | MG | да | ч | `W` | `D·W / C` |
| 5 | мг/ч | MG | нет | ч | `1` | `D / C` |
| 6 | мг/мин | MG | нет | мин | `60` | `D·60 / C` |
| 7 | ЕД/ч | UNIT | нет | ч | `1` | `D / C` |
| 8 | ЕД/кг/ч | UNIT | да | ч | `W` | `D·W / C` |
| 9 | ЕД/мин | UNIT | нет | мин | `60` | `D·60 / C` |
| 10 | мэкв/ч | MEQ | нет | ч | `1` | `D / C` |
| 11 | г/ч | G | нет | ч | `1` | `D / C` |
| 12 | МЕ/ч | IU | нет | ч | `1` | `D / C` (токен `IU`, не `UNIT`) |

**CALC-08.** Формулы прямого и обратного пересчёта — обратные функции друг друга; это проверяется property-тестом (TEST-CALC-12).

### 6.3 Размерностный контроль (обязательный валидатор)

| ID | Правило | Поведение при нарушении |
|---|---|---|
| CALC-10 | `C` выражена в тех же единицах количества, что `amountUnit` схемы (мкг/мл ↔ мкг/кг/мин) | Ошибка `UNIT_MISMATCH`, расчёт заблокирован, MSG-09; «тихая» конвертация ⛔ |

| CALC-13 | `R > 999,9 мл/ч` — технический предел | Жёсткая блокировка, MSG-03 |

### 6.7 Уровни пределов (как вычисляются)

`K_crit` — проектный коэффициент ⚠️ (OQ-5), по умолчанию `3,0`: кратность превышения верхней границы диапазона, после которой предупреждение становится критическим. Мягкое предупреждение включается при **любом** превышении `doseMax` ⚠️ (OQ-4 — не создаёт ли это усталость от предупреждений). Уровни выше подсказки активируются **только** если у схемы задан `doseMax` из источника.

| Уровень | Условие | Поведение | Текст |
|---|---|---|---|
| 0. Подсказка (hint) | всегда, если `doseMin`/`doseMax` заданы | постоянная строка под полем | MSG-12 |
| 1. Предупреждение (soft) | `doseMax < D ≤ doseMax × K_crit` | жёлтый баннер, статус «выше диапазона», расчёт не блокируется | MSG-01 |
| 2. Критическое (critical) | `D > doseMax × K_crit` или `R` близко к техническому пределу | красный баннер + красный статус, расчёт не блокируется | MSG-02/03 |
| 3. Жёсткий предел (hard) | `D > maxDose` или `R > maxRate` при наличии источника | **блокировка** с объяснением | MSG-02 |
| 4. Технический предел | `R > 999,9`; `W ∉ [0,3; 300]`; `C ≤ 0`; `D ≤ 0` | **блокировка** всегда | MSG-03/05/07 |

Приоритет сообщений: технический предел → жёсткий предел → ошибка ввода → критическое → предупреждение → информация. Одновременно показывается не более одного баннера дозового уровня (самый высокий).

### 6.8 Ограничения расчётной модели (явные)

| # | Ограничение | Следствие |
|---|---|---|
| 1 | Не моделируется фармакокинетика, полувыведение, кумуляция, тахифилаксия | Приложение считает скорость введения, не концентрацию в плазме |

### 9.4 Сценарии TalkBack (обязательные)

1. Открыть S-2 → первым читается результат: «Результат не рассчитан, укажите вес и дозу».
2. Ввести вес `70` → «Вес 70 килограммов»; ввести дозу → через 600 мс объявление результата с единицей и статусом.
3. Правка вычисленного поля → роль поля меняется: «Скорость, 2,6 миллилитра в час, введено вручную».
4. Ошибка веса → объявление ошибки без потери фокуса.
5. Предупреждение о дозе → читается сразу после результата, без перевода фокуса.
6. Список → строка одним узлом, звезда — отдельным с состоянием «в избранном/не в избранном».
7. Удаление → диалог читает название препарата; после — снекбар с «Вернуть».

### A.3 Процедура пополнения каталога (обязательна)

1. Открыть первоисточник: инструкция DailyMed SPL (`drugInfo.cfm?setid=…`) и/или RU-инструкция (ГРЛС/РЛС — OQ-18).
2. Зафиксировать `sourceTitle`, `sourceDate`, редакцию.
3. Перенести **только** разделы «Дозировка и способ применения», «Формы выпуска», «Способ приготовления».
4. Единицы схемы — строго как в источнике; если источник использует две схемы — завести две `DoseScheme` с разными `indication`.
5. Диапазоны — как в источнике; жёсткий предел — только если он прямо задан источником/протоколом.
6. Заметки — только цитируемые ограничения (место введения, необходимость ЦВК, скорость титрации, запрет капельных систем).
7. Поставить `verification = VERIFIED` и `verifiedAt`; второй рецензент подтверждает (принцип двойной проверки high-alert ✅).
8. Если источник недоступен — карточка не создаётся; допускается карточка-кандидат **без чисел** со статусом `NEEDS_REVIEW`.
